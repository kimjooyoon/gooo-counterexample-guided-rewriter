# Release policy

The repository immutable-releases setting is enabled through GitHub's repository administration API. The setting guard fails closed when the endpoint is unavailable, the response is missing `enabled`, or the value is not `true`. The release guard fails closed when the published Release API response is missing `immutable` or does not report `true`.

v0.1.0 predates the repository setting and is intentionally preserved as-is with its original `immutable=false` API value. Immutable release `v0.1.1` (release ID `380240322`) is preserved with `gooo-counterexample-guided-rewriter-v0.1.1.tar.gz` (`sha256:2019d42b7050f2c894f839d9c87c261291b43bd54eb7251e11e8485059b907cf`) and its `.sha256` sidecar (`sha256:a12ef67f3b6ffcae9b33cb26072fe60d70a6a37dd35712a01279e634248187b4`). New changes follow a PR-first green path; the default branch preserves prior evidence, and the next release is draft-first before immutable publication. Public release deletion, retagging, overwriting, and asset replacement are forbidden.

The immutable v0.1.3 release (release ID `381184181`, commit `12f22e92fded26a12321001f82cbbc84f154c620`) is preserved. Its release evidence also records the cancelled v0.1.3 run `33621541572` at commit `a0093d23c0c1d1ffa830cc0fae46408437d4bb33`, the failed v0.1.2 run `33621308409` at commit `2d26d9a244140ea27645ae09d979f192e95043fa`, and the `TAG_DELETED_AND_VERSION_REUSED` operational refutation. The first v0.1.4 attempt (`33628688941`, commit `3cf1b3ea939132ce46383b5dcf0585e637827a6e`) is preserved as a failed lineage-preflight attempt, v0.1.5 (`33629041235`, commit `2fee920c3b74b56687fb322ebbac5b3a1fb02504`) as a failed timing-setup attempt, and v0.1.6 (`33629309004`, commit `6a926a584421d0afcf23f030246caefddf5e0072`) as a failed Actions-metrics-output attempt; the next successful patch release must use a fresh version. Missing retained artifacts are represented as null plus UNKNOWN; historical records are not rewritten or deleted.

All generation and before/after validation run in pull-request and default-branch Actions. The runtime reports zero repository writes, zero local test executions, and zero required cross-project gates. Its only output is the caller-owned output directory.

Each fresh release packages the caller-owned conformance output as release evidence. The bundle includes the exact twelve case mappings, four complete UNKNOWN records, the semantic metrics dossier, and an Actions receipt with `build_ms`, `test_ms`, `wall_ms`, `peak_rss_kib`, `cache_hits`, and `cache_misses`; unavailable fields are null with an accompanying UNKNOWN record.
